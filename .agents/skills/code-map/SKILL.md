# 파일 역할과 기능 흐름 관리

대상 프로젝트의 `docs/code-map.md`를 유지한다. 다른 위치에 같은 목적의 문서가 있으면 그 문서를 사용하고 중복 생성하지 않는다. 작업 시작 시 읽고, 기능 수정 완료 전에 관련 행과 흐름을 갱신한다. 기존 지침에는 이 스킬 진입점과 문서 경로만 추가한다.

## 문서를 작성할 때

- 실제 파일 목록과 import/export, 호출부, API·저장소 연결을 읽는다. 이름만 보고 역할을 추측하지 않는다. `.tsx/.ts`를 강제하지 않고 현재 스택의 확장자를 사용한다.
- 첫 부분에 읽기 순서, 실행 진입점, 현재 사용하는 서버·저장소를 적는다. 준비 중인 코드와 실제 운영 기능을 구분한다.
- 표의 첫 열은 프로젝트 기준 상대 경로를 백틱으로 감싼다. 파일 하나당 한 행으로 `파일 / 역할 / 연결되는 파일·기능 / 수정할 때`를 정리한다. 문법을 몰라도 찾을 수 있도록 한국어로 짧게 쓴다.
- 사용자의 주요 행동별로 화면 입력, API, 처리, 저장, 화면 반영 순서를 설명한다. 화면·훅·공통 컴포넌트·스타일·서버·DB·설정·테스트를 구분하고 중요한 데이터 보존 규칙을 적는다.
- 의존성·빌드 결과·캡처·개인 데이터·키·쿠키·환경변수 값은 수집하지 않는다. 필요한 환경변수는 이름과 용도만 적는다.

## 기능을 변경한 뒤

추가·삭제·이동한 파일, 변경된 책임, API·DB·인증·외부 서비스의 흐름을 반영한다. 역할이 유지된 수정은 설명을 불필요하게 늘리지 않고 해당 행과 흐름을 검토한다. 검증한 기능과 남은 연결 작업도 최신 상태로 맞춘다. 변경 기록을 무한히 덧붙이지 않고 현재 구현을 설명한다.

파일과 문서의 누락·오래된 상태는 포함된 검사기로 확인한다. 대상 프로젝트 루트에서:

```powershell
node .agents/skills/code-map/scripts/check-code-map.mjs --root .
# 사람이 코드와 역할 설명을 검토한 다음에만 검토 기준을 갱신한다.
node .agents/skills/code-map/scripts/check-code-map.mjs --root . --stamp
```

문서 위치가 다르면 `--map docs/다른-이름.md`를 지정한다. 파일 목록 확인에는 `--list`를 쓴다. 기본 제외 폴더 외의 생성 전용 경로는 `--exclude 상대/폴더`로 제외하고 문서에 이유를 적는다. TS 선언 파일도 기본 대상이므로 생성된 파일일 때만 그 경로를 제외한다.

검사기는 역할 설명을 작성하거나 의미를 검증하지 않는다. 소스 내용이 달라지면 재검토를 요청하는 지문을 문서 끝의 숨김 주석에 저장한다. 누락·삭제·중복 행이 있으면 `--stamp`로 통과시키지 못한다. 코드 수정 없이 문서만 다듬은 경우에도 경로·흐름을 확인한다.

AGENTS.md와 이 스킬은 이를 읽는 코딩 작업에서 갱신을 요구한다. 에디터 밖의 변경까지 스스로 감지해 문장을 작성하는 백그라운드 Hook이라고 설명하지 않는다. 기존 QA·Stop Hook을 덮어쓰거나 전역 설정을 바꾸지 않는다.
